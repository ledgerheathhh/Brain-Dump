## Lesson 1: Architecture Map

Pi should be understood as four cooperating layers:

1. `packages/coding-agent`: the user-facing `pi` CLI. It owns terminal workflow, slash commands, settings, sessions, skills, extensions, and SDK-facing behavior.
2. `packages/agent`: the reusable stateful agent runtime. It owns turns, message history, event streaming, tool execution, hooks, steering, and follow-up control.
3. `packages/ai`: the provider-neutral model layer. It hides differences between OpenAI, Anthropic, Google, and compatible providers behind one API.
4. `packages/tui`: the terminal UI library. It handles rendering, editor input, markdown, overlays, keyboard/focus behavior, and terminal image support.

The key boundary is this: provider adapters produce model events and tool-call requests, but the agent runtime validates and executes tools. The CLI observes agent events and persists/render them through session storage and TUI components.

High-level prompt flow:

```text
terminal input
  -> coding-agent CLI/editor
  -> session/user message
  -> pi-agent-core turn
  -> pi-ai provider stream
  -> optional tool calls
  -> tool results appended to context
  -> optional follow-up model turn
  -> events rendered by TUI and saved into session
```
